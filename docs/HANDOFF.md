# Подключение команды

Сначала запустите `docker compose up --build`, откройте `/docs` и выполните запросы из [examples/api.http](../examples/api.http). Для короткой инструкции владельцу backend см. [ROLE_1.md](ROLE_1.md), для HTTP — [API.md](API.md).

Для объединения уже существующих веток команды используйте [INTEGRATION.md](INTEGRATION.md): там зафиксированы порядок, владельцы общих файлов и реальные несовпадения DOCX/QA.

## Кто с чем работает

| Роль | Что уже предоставлено ролью 1 | Что участник подключает |
| --- | --- | --- |
| 1 · Техлид/backend | FastAPI, контракты, транспорт LLM, ошибки, кэш, Compose, проверки | Согласовывает изменения контракта и объединяет модули |
| 2 · ИИ и безопасность смысла | `ContentPolicy`, `ModelOutput`, `TextProcessor`, один повтор при неверном ответе | Промпт, независимое извлечение/сверку фактов, доказуемые правила исправлений |
| 3 · DOCX | Подключённый генератор, 4 типа, 2 оформления, граница renderer | Сверенные структуры/шаблоны, правила вёрстки и проверку файлов |
| 4 · Frontend | Существующие пути API, каталог, единые ошибки, TypeScript-контракт | Трёхшаговый UX, состояния ИИ, localStorage, адаптивность от 320 px |
| 5 · QA и данные | Тестируемая сборка приложения и подменяемый LLM-клиент | Грязные черновики, сценарии 1–6, проверки фактов и визуальный QA |
| 6 · Документация и питч | README, архитектурная схема, API и демонстрационные запросы | Демо-историю, презентацию и репетицию |

## Общая точка сборки

```python
create_app(
    settings=None,
    *,
    processor=None,
    content_policy=None,
    renderer=None,
) -> FastAPI
```

Импорт: `from app.main import create_app`. Все аргументы необязательные: обычный запуск использует `.env` и штатный генератор. Передавайте либо готовый `processor`, либо `content_policy` для встроенного транспорта; одновременная передача этих двух аргументов — ошибка конфигурации.

Для своего модуля сборки создайте, например, `backend/app/team_app.py`, импортируйте реализации команды и присвойте результат `create_app(...)` переменной `app`. Запускайте `python -m uvicorn app.team_app:app --reload`. В обычном запуске используется `app.main:app`.

В Docker задайте `APP_MODULE=app.team_app:app` в `.env` и выполните `docker compose up --build -d`. Compose запустит вашу точку сборки: правки маршрутов и Dockerfile не нужны. `APP_MODULE` относится к Compose и не является настройкой провайдера LLM. Обычный `APP_MODULE=app.main:app` сохраняет штатный запуск.

## Роль 2: ИИ и смысл

Транспорт уже реализован. Не нужно повторять обработку HTTP, ключа, таймаута, JSON и ошибок. Контракт ответа модели находится в `app.content_policy.ModelOutput` и экспортируется в `contracts/llm-output.schema.json`:

```json
{
  "requisites": {"subject": "О закупке мониторов"},
  "body": ["Прошу согласовать закупку двух мониторов."],
  "changes": []
}
```

Политика реализует три метода:

```python
from app.content_policy import ModelOutput, PolicyViolation
from app.schemas import ProcessRequest

class TeamContentPolicy:
    def system_prompt(self) -> str:
        ...  # Инструкция модели от роли 2.

    def validate(self, request: ProcessRequest, result: ModelOutput) -> None:
        ...  # Независимая проверка; при нарушении raise PolicyViolation(...).

    def warnings(self) -> list[str]:
        ...  # Предупреждения о реально выполненных проверках.
```

Этот фрагмент показывает интерфейс, а не готовую проверку фактов. После реализации передайте `content_policy=TeamContentPolicy()` в `create_app` и выберите `TEXT_PROCESSOR=openai`. До передачи собственной политики действует `PreserveSourcePolicy`: только точное сохранение текста и реквизитов.

Политика проверяется после Pydantic. Она должна подтверждать факты исходником и ответами пользователя, учитывать отрицания и условия, отличать отсутствие значения от выдуманного. Ошибка политики участвует в общем ограничении: максимум один повтор LLM, затем явная ошибка. Не добавляйте внутренние повторы поверх транспорта.

Для полной замены обработки реализуйте `TextProcessor.process(request: ProcessRequest) -> ProcessorResult` и `close() -> None`, затем передайте экземпляр через `processor=`. `ProcessorResult` из `app.processing` содержит `document`, `changes`, `warnings`, `processor_mode`. Возвращайте валидный `DocumentContent`; заполнение списка недостающих полей выполняет общий конвейер. Не помещайте оформление DOCX в ответ модели.

Для тестов или собственной сборки доступен `get_processor(settings, content_policy=..., client=...)` из `app.processing`. Переданный `httpx.Client` закрывает вызывающая сторона; штатный транспорт закрывает собственный клиент при завершении приложения.

## Роль 3: DOCX

Сохраните сигнатуру callable `DocumentRenderer` из `app.ports`:

```python
def generate_docx(
    content: DocumentContent,
    doc_type: DocumentType,
    template: Template,
) -> bytes:
    ...
```

Импортируйте модели из `app.schemas`, а готовую функцию передайте как `create_app(renderer=generate_docx)`. Генератор принимает содержание и возвращает байты DOCX. Не обращайтесь в нём к LLM и не исправляйте факты. Отсутствующий обязательный реквизит обозначайте `[Заполнить: поле]`.

Типы находятся в `backend/app/doc_types/`, оформления — в `backend/app/templates/`. Добавление YAML с уникальным `id` обновляет каталог после перезапуска. Каждый реквизит, `title` и `body` должны присутствовать в `blocks` типа ровно один раз. Оформление не должно содержать текст или значения реквизитов. Новые расположения блоков или колонтитулы могут потребовать расширения `Template` и генератора.

Проверьте 4 × 2 сочетания, длинный текст, кириллицу, поля, переносы, заголовок и отсутствие обрезанных реквизитов в Word/LibreOffice. Проверьте установленные шрифты. Структурные автотесты не заменяют просмотр страниц.

## Роль 4: Frontend

Последовательность: `GET /api/catalog` → `POST /api/process` → `POST /api/documents/download`. Используйте `document` из ответа обработки для скачивания. Изменение оформления не требует повторного `/api/process`; изменение текста, типа или реквизитов сбрасывает подготовленный результат.

Ошибки всегда содержат строковый `detail`, поэтому текущий интерфейс продолжает показывать понятный текст. Для новых состояний используйте `error.code`, `error.retryable` и `error.request_id`. При ошибке сохраняйте ввод; повтор запускайте действием пользователя. В каталоге `processor_mode` указывает режим, а `warnings` в результате описывает ограничения конкретной обработки.

Источник типов API — `contracts/api.ts`; экспорт пишет его точную копию в `frontend/src/generated/api.ts` внутри контекста Docker-сборки frontend. `frontend/src/types.ts` реэкспортирует эти типы и хранит только собственный `DraftState`. Импортируйте типы через этот файл; не поддерживайте новый параллельный контракт вручную. `--check` проверяет обе генерируемые копии. При разработке через Vite `/api` проксируется в backend. Для другого адреса frontend задайте `CORS_ORIGINS` как JSON-массив разрешённых origins.

## Роль 5: тесты и данные

Подключайте фальшивый процессор в `create_app` или `httpx.MockTransport` в LLM-клиент. В обычных автотестах не нужны ключ API, интернет и запущенная модель. Содержательные проверки транспорта должны покрывать ответ JSON, неверную схему, нарушение политики, предел одного повтора, таймаут, отказ авторизации, перегрузку и отсутствие повторов на сетевой ошибке.

| Сценарий | Проверка |
| --- | --- |
| 1 · Полный путь | Черновик → реквизиты → DOCX; файл открывается и редактируется |
| 2 · Орфография и стиль | В `stub` исходник сохраняется; с политикой роли 2 ошибки исправляются без изменения фактов |
| 3 · Недостающие реквизиты | Пустые обязательные поля получают метки; подтверждённые значения сохраняются |
| 4 · Все типы | У четырёх типов разные нужные поля и порядок блоков |
| 5 · Смена оформления | Содержание двух DOCX совпадает; оформление различается; нового LLM-вызова нет |
| 6 · Отказ LLM | Понятная ошибка, сохранённый ввод, работающий повтор; неверный результат не выдаётся за успех |

Дополнительно проверьте `X-Request-ID`, все классы ошибок, истечение и предел кэша, CORS, readiness, лимит одновременных обработок. Браузерные сценарии: перезагрузка восстанавливает ввод, переключение типов сохраняет их реквизиты, ширина 320 px без горизонтального переполнения, клавиатурная навигация.

## Роль 6: демо и документация

Данные в `examples/` вымышленные. На демонстрации явно называйте режим: `stub` сохраняет текст, `openai` подключает модель, а содержательные гарантии определяет подключённая политика. Не заявляйте проверку смысла или стандарт оформления, пока соответствующий участник их не реализовал и не проверил.

## Совместные изменения

1. Делайте небольшие ветки по своей области и описывайте изменение поведения в PR.
2. Источник API — Pydantic. После изменения схем выполните `scripts/export_contracts.py`, обновите примеры и согласуйте изменение с frontend.
3. Перед объединением выполните backend-проверки, проверку экспорта контрактов и сборку frontend по README.
4. Не добавляйте в Git `.env`, ключи, реальные документы и локальные зависимости.

Команды проверки находятся в [README.md](../README.md). Наличие сценария в этом документе не означает, что ручная проверка уже выполнена.
