# Модель на компьютере в другой сети

Когда сервис и модель стоят в разных сетях, адреса вида `192.168.0.22` не работают: такой
адрес виден только внутри своей сети. Нужна общая частная сеть поверх интернета. Здесь
используется [Tailscale](https://tailscale.com): бесплатно для личного использования,
не требует настройки роутера, трафик шифруется, посторонние в сеть не попадают.

Машине заранее назначается постоянное имя `model-host`. Сервис обращается к
`http://model-host:11434/v1`, поэтому после подключения ничего согласовывать не нужно:
адрес не меняется и работает сразу.

Разделы «Заранее» выполняет владелец сервиса, раздел «Настройка» — человек с той машиной,
самостоятельно и без чьей-либо помощи.

## Заранее, до передачи гайда

1. Заведите аккаунт на [tailscale.com](https://tailscale.com) и войдите в админ-консоль.
2. Откройте вкладку **DNS** и проверьте, что **MagicDNS** включён. Без него имя `model-host`
   не будет resolve-иться; у новых аккаунтов он включён по умолчанию.
3. Откройте **Settings → Keys → Generate auth key**. Включите **Reusable**, срок оставьте
   по умолчанию. Скопируйте ключ вида `tskey-auth-...`.
4. Впишите ключ в шаг 4 ниже вместо `ВСТАВЬТЕ_КЛЮЧ` и передайте гайд помощнику.
   Ключ пускает новое устройство в вашу сеть, поэтому не публикуйте его в общем чате.
5. Установите Tailscale на свой компьютер и войдите в тот же аккаунт.
6. В `.env` проекта укажите:

   ```sh
   TEXT_PROCESSOR=llm
   LLM_BASE_URL=http://model-host:11434/v1
   LLM_MODEL=qwen2.5:7b-instruct
   LLM_TIMEOUT_SECONDS=180
   ```

   Таймаут здесь больше обычного: к времени работы модели добавляется передача по сети.

## Настройка на компьютере с моделью

Нужно примерно 6 ГБ свободного места и 8 ГБ оперативной памяти. Все шаги делаются один раз.

### Шаг 1. Установить Ollama

- **Windows и macOS**: скачайте установщик с [ollama.com/download](https://ollama.com/download)
  и пройдите установку обычным образом.
- **Linux**: `curl -fsSL https://ollama.com/install.sh | sh`

### Шаг 2. Скачать модель

Откройте терминал (в Windows — «Командная строка») и выполните:

```sh
ollama pull qwen2.5:7b-instruct
```

Скачивается около 4.7 ГБ, это занимает от нескольких минут до получаса. Если компьютер
слабый или места мало, возьмите `qwen2.5:3b-instruct` и сообщите об этом владельцу сервиса:
имя модели указывается у него в настройках.

### Шаг 3. Разрешить Ollama принимать запросы по сети

По умолчанию Ollama отвечает только своему же компьютеру. Выполните команду для своей
системы, затем **полностью закройте и снова запустите Ollama** (значок в трее или в строке
меню, пункт Quit, затем запуск заново).

```sh
launchctl setenv OLLAMA_HOST 0.0.0.0     # macOS
setx OLLAMA_HOST 0.0.0.0                 # Windows
sudo systemctl edit ollama               # Linux, см. ниже
```

Для Linux в открывшемся редакторе впишите эти две строки, сохраните и выполните
`sudo systemctl daemon-reload && sudo systemctl restart ollama`:

```
[Service]
Environment="OLLAMA_HOST=0.0.0.0"
```

### Шаг 4. Подключить компьютер к частной сети

Установите Tailscale с [tailscale.com/download](https://tailscale.com/download), затем
выполните команду для своей системы. Вместо `ВСТАВЬТЕ_КЛЮЧ` подставлен ключ владельца
сервиса — он в этом файле уже должен быть.

```sh
# macOS
/Applications/Tailscale.app/Contents/MacOS/Tailscale up --authkey=ВСТАВЬТЕ_КЛЮЧ --hostname=model-host

# Windows (Командная строка)
"C:\Program Files\Tailscale\tailscale.exe" up --authkey=ВСТАВЬТЕ_КЛЮЧ --hostname=model-host

# Linux
sudo tailscale up --authkey=ВСТАВЬТЕ_КЛЮЧ --hostname=model-host
```

Имя `model-host` обязательно: по нему сервис и будет обращаться к модели.

### Шаг 5. Проверить, что всё поднялось

Выполните три команды. Ожидаемый результат подписан под каждой.

```sh
tailscale ip -4
# адрес вида 100.x.x.x — компьютер в частной сети

curl http://localhost:11434/api/tags
# список моделей, в нём должна быть qwen2.5:7b-instruct

curl http://model-host:11434/api/tags
# тот же список, но уже по имени: значит имя работает
```

В Windows вместо `curl` можно открыть эти адреса в браузере, результат тот же.
Если третья команда не отвечает, а вторая отвечает, напишите об этом в ответе:
скорее всего, в настройках сети владельца выключен MagicDNS.

### Шаг 6. Запретить компьютеру засыпать

Спящий компьютер модель не отдаёт. Оставьте его включённым и отключите автоматический сон.

- **Windows**: Параметры → Система → Питание → «Спящий режим» → Никогда.
- **macOS**: Системные настройки → Аккумулятор или Экономия энергии → запретить
  автоматический сон при питании от сети. Можно проще: оставить открытым терминал
  с запущенной командой `caffeinate -s`.
- **Linux**: в настройках питания выключить автоматический переход в сон.

Ollama и Tailscale после установки запускаются вместе с системой сами, отдельно
включать их после перезагрузки не нужно.

### Шаг 7. Что сообщить в ответ

Одно сообщение с тремя строками:

1. «model-host подключён».
2. Вывод команды `tailscale ip -4`.
3. Какая модель скачана: `qwen2.5:7b-instruct` или другая.

## Проверка со стороны сервиса

Когда владелец сервиса вернётся, проверка занимает одну команду из папки проекта:

```sh
python3 scripts/check_llm.py
```

Скрипт берёт адрес и модель из `.env`, показывает список моделей на сервере и прогоняет
один черновик. Ожидаемый конец вывода: «Проверка пройдена: сервер отвечает строгим JSON
и держит факты». Если связи нет, скрипт скажет, что именно не работает.

## Если Tailscale установить нельзя

Например, компьютер рабочий и установка программ запрещена. Тогда подойдёт временный
туннель Cloudflare, он не требует прав администратора:

```sh
cloudflared tunnel --url http://localhost:11434
```

Команда напечатает адрес вида `https://что-то.trycloudflare.com`. Его нужно передать
владельцу сервиса, он пропишет `LLM_BASE_URL=https://что-то.trycloudflare.com/v1`.

Важные ограничения этого способа: адрес меняется при каждом запуске команды, окно
терминала должно оставаться открытым, а сам адрес открыт всему интернету без пароля.
Пока туннель работает, любой человек со ссылкой может пользоваться вашей моделью.
Поэтому он годится как запасной вариант на время демонстрации, а не как постоянный.

## Если что-то не работает

| Что видно | В чём причина | Что сделать |
| --- | --- | --- |
| `curl http://localhost:11434/api/tags` не отвечает | Ollama не запущена | Запустить Ollama, повторить шаг 5 |
| Список моделей пуст | Модель не скачана | Повторить шаг 2 |
| `tailscale ip -4` ничего не печатает | Компьютер не вошёл в сеть | Повторить шаг 4, проверить ключ |
| Ключ отвергнут | Срок ключа истёк или он не reusable | Запросить у владельца новый ключ |
| Имя `model-host` не отвечает, а `localhost` отвечает | Выключен MagicDNS | Сообщить владельцу сервиса |
| Сервис отвечает «Модель не ответила за отведённое время» | Компьютер уснул или очень медленный | Шаг 6, либо модель поменьше |

## Про безопасность

Внутри Tailscale трафик шифруется и доступен только устройствам того же аккаунта, поэтому
черновики документов не видны посторонним. Ollama при этом слушает все интерфейсы, значит
в общей сети вроде кафе или коворкинга её видно и соседям: держите включённым обычный
брандмауэр системы. Ключ `tskey-auth-...` — это пропуск в частную сеть, он не должен
попадать в публичные чаты и в репозиторий.
