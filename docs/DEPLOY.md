# Развёртывание: модель на другом компьютере, сайт в сети

Два разных вопроса, их удобно решать по очереди. Первый нужен сейчас: обработка уезжает
на компьютер, где уже скачана модель. Второй — на будущее: открыть сайт для других людей.

## Часть 1. Обработка на другом компьютере

Подробные шаги для владельца той машины лежат в [REMOTE_MODEL.md](REMOTE_MODEL.md).
Здесь только то, что нужно сделать нам и в каком порядке.

### Что делает владелец машины с моделью

1. Разрешает Ollama отвечать по сети: `OLLAMA_HOST=0.0.0.0`, затем перезапуск Ollama.
2. Подключает компьютер к общей частной сети (Tailscale) под именем `model-host`.
3. Запрещает компьютеру засыпать: спящая машина модель не отдаёт.
4. Сообщает, какая именно модель у него скачана.

### Что меняем мы

В `.env` проекта:

```sh
TEXT_PROCESSOR=llm
LLM_BASE_URL=http://model-host:11434/v1
LLM_MODEL=<имя модели с той машины>
LLM_TIMEOUT_SECONDS=180
```

Имя модели должно совпасть с тем, что скачано на той машине, иначе сервис ответит
подсказкой «выполните ollama pull». Таймаут больше обычного: к работе модели добавляется
передача по сети.

### Как убедиться, что всё работает

```sh
python3 scripts/check_llm.py
backend/.venv/bin/python scripts/quality_report.py
```

Первая команда проверяет связь и один черновик. Вторая прогоняет эталонный набор и даёт
число: если на той машине другая модель, сравните его с нашими 49 проверками из 54.
Промпт настроен под `qwen2.5:7b-instruct`, на другой модели результат может отличаться.

### О чём помнить

Длинный черновик режется на части, и каждая часть — отдельный запрос по сети. Задержки
складываются. Для показа берите короткие черновики, на длинных предупреждайте зрителей.

## Часть 2. Сайт в сети

Сейчас всё привязано к локальному компьютеру: и `compose.yaml`, и сервер разработки
слушают только `127.0.0.1`. Это осознанно. Ниже три уровня открытости, от простого
к постоянному.

### Уровень 1. Локальная сеть, для показа на месте

Годится, когда зрители в той же сети Wi-Fi.

1. В `compose.yaml` у сервиса `frontend` убрать привязку к локальному адресу:
   `"8080:80"` вместо `"127.0.0.1:8080:80"`. Порт backend наружу открывать не нужно,
   в него ходит nginx внутри сети Docker.
2. В `frontend/nginx.conf` поднять `proxy_read_timeout` с 35 секунд до 300.
   **Это обязательно**: подготовка документа занимает от 8 секунд до нескольких минут,
   и на 35 секундах nginx оборвёт запрос, хотя модель продолжит работать.
3. Разрешить входящие подключения, если система спросит про брандмауэр.
4. Узнать адрес компьютера (`ipconfig getifaddr en0` на macOS, `hostname -I` на Linux)
   и открыть `http://<адрес>:8080` с любого устройства той же сети.

Риск: в этой сети сайт доступен всем без пароля, включая посторонних в кафе
или коворкинге.

### Уровень 2. Временный публичный адрес, для показа издалека

```sh
cloudflared tunnel --url http://localhost:8080
```

Команда печатает адрес вида `https://что-то.trycloudflare.com`. Ни роутер, ни права
администратора не нужны. Адрес меняется при каждом запуске, окно терминала должно
оставаться открытым, пароля нет: ссылка работает у любого, кто её получил.
Годится на время демонстрации, не как постоянное решение.

### Уровень 3. Постоянное размещение, после хакатона

1. Сервер с публичным адресом, `docker compose up -d`, домен.
2. HTTPS: Caddy или nginx с сертификатом, иначе черновики идут по сети открытым текстом.
3. Пароль: хотя бы базовая авторизация на nginx, лучше вход по учётной записи.
4. Ограничение частоты запросов (`limit_req` в nginx). Это не формальность: Ollama
   выполняет запросы по одному, я это замерял — три одновременных заняли столько же,
   сколько три подряд. Один человек с длинным черновиком займёт очередь для всех.
5. Модель: либо на том же сервере, либо в частной сети с ним. Через интернет без
   шифрования черновики отправлять нельзя.

## Обязательный минимум перед открытием наружу

| Что | Почему | Чья область |
| --- | --- | --- |
| `proxy_read_timeout` не меньше таймаута подготовки | Иначе долгие документы обрываются | Роль 1 |
| Ограничение частоты запросов | Модель обслуживает запросы по одному | Роль 1 |
| Пароль или вход | Сейчас доступа нет ни у кого и ни у чего | Роль 1 |
| Показ хода работы в интерфейсе | Ожидание в минуты выглядит как зависание | Роль 4 |
| Решение, чей компьютер обрабатывает черновики | Владелец машины технически видит запросы | Команда |

Чего делать не нужно: базы данных, хранения документов и очередей. Файлы создаются
в памяти на время запроса, на сервере ничего не остаётся.
