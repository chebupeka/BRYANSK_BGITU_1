# Роль 1: что передать команде

Ваша рабочая часть — backend, договорённость об API, подключение LLM и общий запуск. В репозитории готовы маршруты FastAPI, единые ошибки, экспорт контрактов, реальные настройки LLM, таймауты и один повтор неверного ответа, кэш с пределом размера/срока, CORS, проверки готовности и Docker Compose.

## Запустить за один шаг

Из корня репозитория, с запущенным Docker:

```sh
docker compose up --build
```

Ключ не нужен. Откройте [интерфейс](http://localhost:8080) и [Swagger](http://localhost:8000/docs), подготовьте пример и скачайте DOCX. Для сквозной проверки выполните `python scripts/check_docker.py` в другом терминале.

| 3 · DOCX | [HANDOFF: роль 3](HANDOFF.md#роль-3-docx), `app/ports.py`, YAML-каталоги | Функция `(content, doc_type, template) -> bytes` через `create_app(renderer=...)` |
| 4 · Frontend | [API](API.md), [типы TypeScript](../contracts/api.ts), [запросы](../examples/api.http) | Каталог → обработка → скачивание; сервер на `localhost:8000` |
| 5 · QA | [сценарии](HANDOFF.md#роль-5-тесты-и-данные), `backend/tests`, `examples/` | Тесты без модели/ключа, затем браузер и DOCX |
| 6 · Документация/питч | [README](../README.md), [архитектура](ARCHITECTURE.md), примеры | Готовит демонстрацию и презентацию по реально подключённым возможностям |

Менять FastAPI-маршруты ради подключения участников не нужно. Общая точка сборки: `create_app(settings=None, *, processor=None, content_policy=None, renderer=None)` из `app.main`. Подробные сигнатуры и правила — в [HANDOFF](HANDOFF.md).

Команда может собрать свои реализации в новом `backend/app/team_app.py` и задать `APP_MODULE=app.team_app:app` в `.env` для Compose. Так каждый модуль подключается через общую сборку без правок маршрутов или Dockerfile.

Уже существующие ветки участников, порядок объединения и конкретные несовпадения DOCX/QA перечислены в [INTEGRATION.md](INTEGRATION.md). Основа роли 1 находится отдельно в `feat/role-1-backend-integration`; совместимость после объединения подтверждается общими проверками.

## Подключить LLM

1. Скопируйте `.env.example` в `.env`.
2. Задайте `TEXT_PROCESSOR=openai`, `LLM_BASE_URL`, `LLM_MODEL` и при необходимости `LLM_API_KEY`.
3. Выполните `docker compose up -d --force-recreate`.
4. Выполните `/api/process` в Swagger: readiness проверяет только локальную конфигурацию.

Для LLM на компьютере адрес из Docker — `http://host.docker.internal:11434/v1`. Для backend без Docker — `http://localhost:11434/v1`. Необязательный профиль Ollama и команды установки выбранной модели описаны в [README](../README.md#необязательная-ollama-в-compose).

**Граница готовности:** транспорт LLM работает; штатная политика пропускает только точное сохранение исходника и реквизитов. Исправление стиля, извлечение и проверка фактов — реализация роли 2. До её подключения не показывайте модель как завершённый смысловой редактор. DOCX-структуры уже работают, сверка оформления с эталонами остаётся роли 3.

## Перед объединением изменений

Из `backend` выполните Ruff и pytest, из `frontend` — `npm run build`. После изменения Pydantic выполните из корня `backend/.venv/Scripts/python.exe scripts/export_contracts.py`, затем ту же команду с `--check`; добавьте обновлённые `contracts/` в изменение. Команды установки и проверки для других систем есть в [README](../README.md).

Для диагностики передавайте участнику `error.code` и `error.request_id`. `503 processor_busy` означает занятые слоты, `504` — таймаут LLM, `502` — отказ провайдера или неверный результат. Ошибка не удаляет ввод пользователя, результат ошибки не попадает в кэш. Не добавляйте `.env`, ключи и реальные документы в Git.

## Проверено при передаче 12 сентября 2026

Прошли 91 тест backend, Ruff, проверка зависимостей, экспорт контрактов и сборка TypeScript/Vite. В отдельном Docker-проекте собраны актуальные образы и пройдены сквозные проверки `stub` и `unavailable` через nginx: готовность, ошибки, повтор обработки, заголовки и скачивание обоих DOCX. Тестовый проект после проверки удалён.

Транспорт LLM проверен через `httpx.MockTransport`, без настоящих моделей и ключей. Смысловые гарантии политики роли 2 и визуальная проверка DOCX в офисном редакторе требуют отдельной приёмки. Сопоставление веток в [INTEGRATION.md](INTEGRATION.md) является планом объединения; сами ветки в этой поставке не объединялись.
