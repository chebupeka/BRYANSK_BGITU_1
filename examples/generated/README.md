# Сгенерированные документы

Готовые DOCX для черновиков из [examples/drafts](../drafts): 13 документов по 12 черновикам из 20.
Все 12 — в оформлении «classic», докладная записка `report_memo_01_structured` — ещё и в «modern».

Документы получены 13.09.2026 на стенде https://doc3.codeboom.pro в режиме обработки `llm`
тем же путём, что проходит пользователь в интерфейсе: подсказка реквизитов из черновика,
обработка текста, выгрузка DOCX. Реквизиты вручную не дописывались: всё, чего сервис не
нашёл в черновике, осталось в документе меткой «[Заполнить: …]».

## Почему документов меньше, чем черновиков

Каждый документ прочитан рядом со своим черновиком. В восьми документах модель добавила
сведения, которых в черновике нет, заменила тему, заданную в черновике, или изменила смысл
фразы — усилила, сузила или переназвала сказанное. Мерка одна для всех: новое сведение,
заменённая тема или изменённый смысл исключают документ, даже если это одно слово;
перефразирование, после которого сказано то же самое, документ не исключает. Эти черновики трижды перегенерированы на
стенде; все три раза документ пришёл с тем же текстом (сервис вызывает модель с нулевой
температурой и постоянным зерном). Показывать документ с дописанными сведениями или
изменённым смыслом нельзя, поэтому эти файлы из примеров убраны:

| Черновик | Что добавила или изменила модель |

## Что проверено

Каждый из 13 файлов открыт через python-docx (текст абзацев, таблиц и колонтитулов) и сверен
с [manifest.yaml](../drafts/manifest.yaml):

- все 13 файлов открываются, текст непустой;
- значения из `must_keep` (даты, суммы, номера, фамилии) найдены в 12 файлах из 13;
  сравнение без учёта регистра и пробелов внутри чисел. Исключение —
  `edge_04_number_formats.docx`, где даты записаны словами (см. таблицу);
- для каждого обязательного реквизита из `not_in_draft` в документе стоит метка
  «[Заполнить: …]»; необязательные реквизиты из `not_in_draft` (организация, назначение)
  в документ не выведены;
- тема, которую черновик задаёт явно (`subject` в `in_draft`), дословно сохранена во всех
  8 файлах, где она задана;
- разговорные обороты и опечатки из этих черновиков («Там всё плохо», «барахлит»,
  «испортится», «темпиратура», «СРОЧНО!!!», решётки markdown, двойные пробелы) в документах
  отсутствуют.

Кроме того, текст каждого из 13 файлов прочитан рядом с черновиком. Добавленных организаций,
должностей, ФИО, дат, сумм, количеств и условий не найдено, темы, заданные черновиком, не
заменены. Отличия, которые остались, — перефразирование в деловой стиль, тема, которую сервис
сформулировал сам там, где черновик её не задаёт, и форма записи дат; они перечислены в
столбце «На что смотреть». Эта сверка ручная: автоматически проверяются только пункты выше.

## Как перегенерировать

Скрипт [scripts/generate_examples.py](../../scripts/generate_examples.py) использует только
стандартную библиотеку Python. Из корня репозитория:

```bash
# локальный сервис (docker compose up --build), адрес по умолчанию http://localhost:8080
python3 scripts/generate_examples.py

# другой адрес; --responses сохраняет ответы /api/process в JSON для разбора
python3 scripts/generate_examples.py https://doc3.codeboom.pro --responses /tmp/responses

# только выбранные черновики (имя файла без .txt, ключ можно повторять)
python3 scripts/generate_examples.py https://doc3.codeboom.pro --only report_memo_02_colloquial
```

Для каждого случая из `manifest.yaml` скрипт вызывает `POST /api/requisites/suggest`,
затем `POST /api/process` с подсказанными реквизитами и `POST /api/documents/download`
с оформлением `classic` (для первого черновика каждого типа по манифесту — ещё `modern`,
в том числе при `--only`), и перезаписывает файлы в этом каталоге. Скрипт создаёт документы
для всех черновиков манифеста, включая восемь убранных выше: после запуска их нужно снова
сверить с черновиком. Между вызовами `/api/process` выдерживается пауза 3,5 секунды;
ответы 429 и 503 и обрывы соединения повторяются через 20 секунд.

Текст меняется только в режиме обработки `llm` (`TEXT_PROCESSOR=llm`); с настройкой по
умолчанию `stub` документы получатся, но без правки текста. Модель вызывается с нулевой
температурой и постоянным зерном, поэтому повторный запуск на том же стенде даёт тот же
текст; после изменений в сервисе или смены модели таблицу выше нужно сверить заново.
