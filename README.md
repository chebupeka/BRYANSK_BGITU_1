# Документ за 3 шага

Основной каркас проекта для передачи команде: черновик → тип документа и реквизиты → скачиваемый DOCX. Работает локально без ключей API и внешних сервисов.

**Это стартовая версия, а не готовый конкурсный MVP.** Обработчик текста — заглушка: сохраняет непустые строки исходника без изменения слов и фактов. Исправление орфографии, деловой стиль, извлечение реквизитов из текста и фактчекинг ещё не реализованы. Интерфейс сообщает об этом до подготовки и скачивания.

## Что работает

- React + TypeScript + Vite, компоненты Ant Design и три этапа работы.
- Четыре типа: служебная записка, докладная записка, информационная справка и письмо.
- Два оформления: «Классический» и «Компактный» с разными шрифтами, полями, интервалами и выравниванием.
- Формы реквизитов из YAML. Вместо недостающих обязательных значений — `[Заполнить: название поля]`; необязательные пустые поля пропускаются.
- Редактируемые абзацы DOCX через python-docx. Дата, номер и подписант автоматически не придумываются.
- localStorage для черновика, выбранного оформления и реквизитов каждого типа. При ошибке данные остаются в форме, доступна повторная попытка.
- Смена оформления использует уже подготовленное содержание и не вызывает обработчик повторно. Изменение текста, типа или реквизитов сбрасывает подготовленный результат.
- FastAPI/OpenAPI, проверки Pydantic, API-тесты и GitHub Actions.

Конфигурации реквизитов и оформления — стартовые. Их нужно сверить с эталонами организаторов: отдельного комплекта таких эталонов в переданных материалах не было. Соответствие конкретному ГОСТ или стандарту организации не заявляется.

## Быстрый запуск через Docker

Нужен запущенный Docker Engine с Compose. Из корня репозитория:

```sh
docker compose up --build
```

- Интерфейс: [localhost:8080](http://localhost:8080).
- Документация API: [localhost:8000/docs](http://localhost:8000/docs).
- Проверка сервера: [localhost:8000/api/health](http://localhost:8000/api/health).

`.env` необязателен для первого запуска; по умолчанию используется `TEXT_PROCESSOR=stub`. Порты привязаны к локальному компьютеру. Остановка: `docker compose down`.

## Локальная разработка

Нужны Python 3.12–3.14 и Node.js 22.12+; в CI используются Python 3.12 и Node.js 24. Зависимости зафиксированы в lock-файлах. Актуальные руководства: [Vite](https://vite.dev/guide/), [FastAPI](https://fastapi.tiangolo.com/tutorial/), [python-docx](https://python-docx.readthedocs.io/en/latest/).

Клонирование:

```sh
git clone https://github.com/chebupeka/BRYANSK_BGITU_1.git
cd BRYANSK_BGITU_1
```

Первый терминал, PowerShell:

```powershell
Copy-Item .env.example .env
cd backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.lock
.venv/Scripts/python.exe -m pip install --no-deps -e .
.venv/Scripts/python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Для Linux/macOS:

```sh
cp .env.example .env
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Второй терминал, из корня репозитория:

```sh
cd frontend
npm ci
npm run dev
```

Откройте [localhost:5173](http://localhost:5173). Vite перенаправляет `/api` на порт 8000; в Docker это делает nginx. CORS для обычного запуска не нужен. Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd` вместо `npm`.

Для проверки production-сборки: `npm run build`, затем `npm run preview` из `frontend`. API должен продолжать работать; интерфейс будет на [localhost:4173](http://localhost:4173).

## Конфигурация

Скопируйте корневой `.env.example` в `.env`. После изменения перезапустите backend; для Compose выполните `docker compose up -d --force-recreate` (оба сервиса, чтобы nginx обновил адрес backend).

| Переменная | Сейчас |
| --- | --- |
| `TEXT_PROCESSOR=stub` | Перенос текста без исправлений, режим по умолчанию |
| `TEXT_PROCESSOR=unavailable` | Ответ 503 при подготовке документа; режим проверки ошибки |
| `LLM_BASE_URL` | Зарезервирован для будущего OpenAI-совместимого провайдера |
| `LLM_MODEL` | Зарезервирован, пока не используется |
| `LLM_API_KEY` | Зарезервирован, пока не используется; секреты не коммитить |

Указание LLM-переменных **не подключает ИИ**. В стартовой версии нет внешних сетевых вызовов обработчика, базы данных или серверного хранения черновиков. Файлы создаются в памяти на время запроса. localStorage сохраняет данные на текущем устройстве до очистки данных сайта; подготовленный результат после перезагрузки нужно получить заново.

## Структура

```text
backend/
  app/
    main.py              # маршруты API и сборка приложения
    schemas.py           # контракты Pydantic
    settings.py          # переменные окружения
    processing.py        # граница TextProcessor и два демонстрационных режима
    catalog.py           # загрузка и проверка конфигураций
    docx_generator.py    # «структура типа × оформление шаблона»
    doc_types/*.yaml     # реквизиты и порядок блоков четырёх типов
    templates/*.yaml     # параметры двух оформлений
  tests/                 # содержательные проверки API и DOCX
frontend/
  src/
    App.tsx              # переходы, состояние и обработка ошибок
    api.ts               # единственная точка HTTP-вызовов
    storage.ts           # восстановление и сохранение черновика
    types.ts             # типы API для интерфейса
    components/          # настройки и просмотр содержания
docs/                    # архитектура, API и задачи команды
examples/                # явно демонстрационные входные данные
compose.yaml
.github/workflows/checks.yml
```

## Проверки

Из `backend` на Windows:

```powershell
.venv/Scripts/python.exe -m ruff check .
.venv/Scripts/python.exe -m pytest -q
```

На Linux/macOS замените `.venv/Scripts/python.exe` на `.venv/bin/python`. Из `frontend`: `npm run build` (включает проверку TypeScript). Те же проверки выполняет GitHub Actions.

Тесты проверяют восемь сочетаний типа и шаблона, сохранение исходных фактов, метки пропусков, введённые реквизиты, отличие оформления без изменения текста, некорректные запросы и отказ обработки. Это структурная проверка DOCX; визуальный вид в Word/LibreOffice проверяется отдельно по [сценариям](docs/HANDOFF.md#проверка-перед-передачей).

### Попробовать вручную

1. Нажмите «Вставить пример» или используйте вход из `examples/service_memo.json`. Это вымышленные демонстрационные данные.
2. Выберите тип и оформление, заполните реквизиты либо оставьте часть пустой.
3. Подготовьте и скачайте DOCX. Убедитесь, что метки пропусков видны, а текст редактируется.
4. Вернитесь к реквизитам, смените только оформление, скачайте второй файл: содержание совпадёт.
5. Установите `TEXT_PROCESSOR=unavailable`, перезапустите backend и попробуйте подготовить изменённый черновик. Должна появиться ошибка. Верните `stub`, перезапустите backend и нажмите «Повторить подготовку».

## Продолжение работы

Для первого прохода команде достаточно прочитать [архитектуру и API](docs/ARCHITECTURE.md), затем [распределение задач и сценарии проверки](docs/HANDOFF.md). Исходный краткий контекст сохранён в [docs/CONTEXT.md](docs/CONTEXT.md).

Добавление типа: создайте `backend/app/doc_types/*.yaml` с уникальным `id`, `name`, `description`, `title`, `fields` и `blocks`. Каждый реквизит, а также `title` и `body` должны присутствовать в `blocks` ровно один раз. Перезапустите backend; форма и генератор подхватят новый тип из каталога. Содержательные правила заполнения нового типа реализуются отдельно в обработчике.

Добавление оформления: скопируйте YAML из `backend/app/templates`, задайте уникальный `id` и измените оформление. Параметры валидируются при запуске. Текст и набор реквизитов в шаблон не помещаются. Новые способы расположения блоков или колонтитулы потребуют расширить контракт Template и генератор.

Следующий главный этап — реализовать LLM-адаптер за `TextProcessor` с JSON-схемой, независимым извлечением/сверкой фактов, не более чем одним повтором при неверном ответе и кэшем по черновику, типу и ответам пользователя. Эти гарантии должны появиться **до** включения реального переписывания текста.

Ограничения: нет авторизации, серверной истории, постоянного кэша, редактирования результата в интерфейсе и защиты для публичного многопользовательского размещения. До такого размещения команда должна выбрать правила доступа, ограничения запросов и хранения документов. Пока проект предназначен для локальной разработки и демонстрации.
